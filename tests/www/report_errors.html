HIGH — crash Paper / Unfold (Slab)
slab		vert, edge, face (all)FAIL Uncaught TypeError: ops[tpState.op] is not a function
topmodjs.html:7333:18
 The popover Apply handler falls through to the generic ops[tpState.op]() at line 7333, but 'slab' has no entry in the ops{} map. Slab/papercraft is normally driven by the fab flow (data-act fabPaper/fabLayers/fabFaces/fabLaser/fabWaffle -> openToolPop('slab') -> previewFab()/syncFabRows()), not by a direct ops['slab'] call.In the #tpApply handler (~line 7333), add a branch for tpState.op==='slab' that calls the fab commit (e.g. previewFab()/bakeFab equivalent) instead of falling through to ops[op](); OR register ops.slab as the papercraft commit. Also guard the fallthrough: if(typeof ops[tpState.op]!=='function'){ /* close + warn */ return; }
HIGH — freeze Remesh/subdivide ops on high-poly primitives
(multiple remeshing ops)		faceFREEZE UI freeze — main thread blocks synchronously >30s (tab unresponsive; required browser restart)
operator mesh rebuild (synchronous)
 Subdivision/remesh operators rebuild the entire mesh synchronously with no upper bound. base_faces x op_multiplier explodes (Menger ~x20, Honeycomb/DoubleStellate ~x7, Catmull/Doo-Sabin/Loop ~x4). On primitives that already have hundreds-to-thousands of faces this produces tens of thousands of faces and locks the UI. 128 of 368 primitive x operator combos exceed a safe ~6000-face budget.Add a pre-op face-budget check with a confirm dialog when projected faces exceed a threshold; OR run heavy remeshes in a Web Worker / chunk with a progress bar and cancel; OR cap subdivision so a single op cannot exceed N faces. Affected primitives: Rossler, Sine-wave, Cymatics, Pseudospherical, Weave, Chain mail, Voronoi, Tree, Gem, Maze, Maze 3D.
